# Ежедневное обучение голосу @ter_cars по правкам в пульте

**Статус:** предложено 04.11.2026; подход выбран владелицей: автоматически брать примеры из правок пульта. Требуется утвердить этот дизайн перед реализацией.

## Намерение

Раз в день учитывать, как владелица реально переписывает сгенерированные посты, и применять эти наблюдения к новым черновикам. Не считать неизменённые, только одобренные или написанные помощником тексты личным стилем владелицы.

## Подтверждённое устройство сейчас

- Пульт хранит посты и признак `edited` в `/opt/threads/ter/state.json`. В состоянии сейчас 7 карточек с правками; события «правка владелицы» отмечены отдельно.
- Журнал истории хранит время и название действия, но не текст до/после. Исходные версии этих 7 карточек нашлись в клоне репозитория `ter-cars` по дате в ID поста; дата публикации могла быть перенесена.
- Пультовый API сейчас требует полный `TER_KEY`, который также разрешает изменять карточки и одобрять публикацию. Передавать его в Actions нельзя.
- GitHub Actions не видит состояние пульта и создаёт посты из репозитория. Поэтому текущая генерация не может сама извлечь твои правки.

## Подходы

1. **Выбран: отдельное чтение примеров из пульта.** Добавить маршрут только для чтения, защищённый отдельным ключом `TER_STYLE_KEY`; он отдаёт только пары «исходник/правка», не открывая API редактирования или одобрения. Daily workflow получает этот снимок и передаёт модели.
2. **Копировать пары в GitHub при каждой правке.** Не нужен запрос к пульту при генерации, но серверу нужны права записи в репозиторий, а исправленные тексты сохраняются в GitHub. Этот путь не выбран.

## Границы и поведение

- При импорте каждого нового черновика пульт сохраняет неизменяемый `original_text`. При первом редактировании — тоже фиксирует текущий текст как исходный, если исходник отсутствует. Последующие правки не заменяют его.
- Для уже имеющихся правленых карточек исходник восстанавливается из сохранённых черновиков репозитория по исходной дате в ID. Неизвестные или несовпавшие версии не используются как обучающие пары.
- Новый маршрут отдаёт только недавние фактические правки: ID, рубрику, исходный текст, итоговый текст и время. Он не отдаёт статусы, токены, фотографии, ссылку аккаунта или остальное состояние. Ключ подходит только для этого маршрута.
- GitHub Actions запрашивает пары перед дневной генерацией. Отдельный второй вызов модели не нужен: в одном ежедневном запросе модель кратко выводит правила из различий «до/после» и применяет их к черновикам. Одобренные и неизменённые посты не считаются примерами правок.
- Примеры передаются только во временном файле runner и в запросе генерации. Их текст не записывается в step summary, логи, репозиторий или артефакты.
- Для текущих 7 правок в клоне нашлись все 7 исходных карточек, если искать по дате в ID, а не по текущей дате публикации.
- Если защищённый endpoint недоступен или ключ не прошёл проверку, дневная генерация всё равно создаёт черновики по утверждённому голосу из `plan/11_голос_маши.md`, а workflow summary явно отмечает, что анализ правок в этот день пропущен. Если правок пока нет, применяется тот же голосовой ориентир.

## Не входит

- Не менять тексты, статусы, расписание или одобрения уже существующих карточек.
- Не публиковать посты автоматически.
- Не обучать модель на неотредактированных черновиках, лайках, пропусках или публикациях без правки.
- Не сохранять новый стиль-профиль публично и не показывать пользователю отдельную панель.

## Проверка

- Unit-тесты проверяют фиксацию исходного текста при импорте и первой правке, сохранение исходника при последующих правках, фильтрацию только изменённых пар и минимальный ответ read-only маршрута.
- Проверить, что ключ стиля не даёт доступ к edit/approve/skip.
- На GitHub Actions проверить получение семи текущих пар без вывода их текста в логи и запуск генератора с примерами.
- Убедиться, что локальные действующие посты и состояния на сервере не переписываются при выкладке.
